# Contributing to Toget

Thanks for taking a look. Toget is at an early stage, so the most useful contributions right now are use cases, bug reports, and design feedback — not large pull requests.

## Before you start

- Open an issue describing what you want to change. For anything larger than a small fix, wait for a maintainer to agree on the approach before writing code.
- Do not include secrets, private keys, customer data, or personal information in issues or pull requests.
- For security issues, follow [SECURITY.md](SECURITY.md) instead of opening a public issue.

## Pull requests

- Keep each pull request focused on one change.
- Add or update tests when behavior changes.
- Update documentation when the public interface changes.
- Use clear commit messages. Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`) are welcome but not required.
- By submitting a pull request, you confirm that you have the right to contribute the code and that it can be distributed under the project's license.

## License and CLA

The project is licensed under the [Apache License 2.0](LICENSE). Contributions are accepted under the same license.

To keep the project able to offer commercial and enterprise editions, we may ask contributors to sign a Contributor License Agreement (CLA) before a pull request is merged. If a CLA is required, it will be provided in the pull request.

## Code of conduct

Be direct, be kind, and assume good faith. Harassment, discrimination, and personal attacks are not welcome. Maintainers may remove comments or contributions that violate this expectation.

## Questions

Open a GitHub issue with the `question` label.
