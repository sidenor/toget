# Contributing to Toget

Thanks for taking a look. Toget is at a very early stage: the design is incomplete, many parts are not built yet, and some ideas will change. That is exactly why we are opening it now — we want people from all over the world to help shape it.

You do not need to be an expert in all of it. Use cases, bug reports, design feedback, documentation, translations, tests, and code are all welcome.

## Good first contributions

- **Tell us your use case.** What are you trying to do with agents, and what gets in the way? Real scenarios are more useful than abstract feature requests at this stage.
- **Critique the design.** Read [docs/](docs/) and tell us where the model is wrong, incomplete, or too complicated. Disagreement is welcome if it is specific.
- **Improve the docs.** Fix unclear passages, add examples, or translate a document.
- **Report bugs.** If something is broken, open an issue with what you expected, what happened, and how to reproduce it.
- **Review security and privacy.** Read [SECURITY.md](SECURITY.md) and [docs/security-model.md](docs/security-model.md). If you find a problem, report it privately first.
- **Write code.** Small, focused fixes are easiest to review. For larger changes, open an issue first so we can agree on the approach.

## Before you start

- Open an issue describing what you want to change. For anything larger than a small fix, wait for a maintainer to agree on the approach before writing code.
- Do not include secrets, private keys, customer data, or personal information in issues or pull requests.
- For security issues, follow [SECURITY.md](SECURITY.md) instead of opening a public issue.
- Be patient. The project is early, and maintainers may not reply immediately.

## Pull requests

- Keep each pull request focused on one change.
- Add or update tests when behavior changes.
- Update documentation when the public interface changes.
- Use clear commit messages. Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`) are welcome but not required.
- By submitting a pull request, you confirm that you have the right to contribute the code, and you agree that your contribution is licensed under the project's license (Apache-2.0, inbound = outbound).

## Code of conduct

Be direct, be kind, and assume good faith. Harassment, discrimination, and personal attacks are not welcome. Maintainers may remove comments or contributions that violate this expectation.

## Questions

Open a GitHub issue with the `question` label. If you are unsure whether something is a bug, a design gap, or a usage question, just ask — at this stage, all three are useful.
